# 六法マーカーアプリ 仕様書 v2

作成日: 2026-09-24（v1: 同日・`Downloads/ropo-marker-app-spec.md` をレビューして改訂）

## 1. 経緯

1. 当初は PC・スマホ両対応の Electron/PWA ハイブリッド構成を想定
2. → PC は使わないと判明し、**Android スマホ専用 PWA** に絞る
3. 市販六法の PDF は紙前提の組版・電子版は DRM 付きで組み込み不可
4. → **e-Gov 法令データを自前レンダリング**する方針に確定
5. 要件を「テキスト表示・3色マーカー・条文番号検索・参照条文リンク」に絞り、PDF 表示自体を不要と判断。React ベースの軽量 PWA とする
6. （v2）レビューで以下を決定: マーカー位置は文字列アンカー方式／条文データは条・項・号の入れ子／バックアップ必須／公開は GitHub Pages／搭載法令は令和8年司法試験用法文登載法令（司法試験専用。司法書士試験・実務用の法令は載せない）

## 2. 目的

司法試験の法文登載法令を、スマホ上でテキストとして読み、3色マーカーでハイライトし、
条文番号検索・参照リンクで素早く行き来できる司法試験学習用アプリ。

## 3. 要件

### 3.1 必須機能
- 条文をテキスト表示（横書き。項番号 ①② ・号 一二 の表示あり）
- 任意範囲への3色マーカー（項・号をまたぐ選択にも対応）
- 条文番号検索（「民709」「民法七百九条」「709の2」「民訴248」等の表記ゆれを正規化）
- 参照条文のリンク化（段階的に実装。§4.5）
- マーカーの書き出し・読み込み（JSON ファイル）

### 3.2 搭載法令
- **e-Gov で取得できるものは全件搭載**する。法令はデータとして扱い、アプリの画面は法令数に依存しない
- 画面の煩雑さは「科目グループ」と「表示する科目の選択（マイ六法）」で解決する
- グループ構成:
  - 公法系／民事系／刑事系（司法試験 必須科目）
  - 選択科目 8 種（倒産・租税・経済・知財・労働・環境・国際公法・国際私法）
- **司法試験の登載法令以外は載せない**（司法書士試験・実務用の法令は不要と確認済み）
- **対象外（当面）**: 条約（国連憲章・ウィーン条約等）と告示（不公正な取引方法）。e-Gov 法令データに収録されていないため（2026-09-24 に API の法令名検索で 0 件を確認）。必要なら後で手動取り込みを検討
- 出典リスト: 法務省「令和8年司法試験用法文登載法令」（`docs/source/001455492.pdf`。手元のみ・git 管理外）

### 3.3 基準時点
- **取り込み時点の最新（現行施行版）**とする
- 参考: 司法試験の登載法令は「試験年の1月1日現在で施行されている内容」（令和8年版の場合）。差が問題になれば `py scripts/fetch_laws.py --asof YYYY-MM-DD` で時点を指定して取り込める（API の `asof` 指定。2026-09-24 に動作確認済み）

### 3.4 非対象
- PC 対応・PDF 表示・縦書き
- 司法書士試験・実務用の法令
- 搭載対象外の法令への参照リンク

## 4. 技術構成

### 4.1 スタック
- 画面: React + Vite（PWA）
- 保存: IndexedDB（マーカー）。起動時に `navigator.storage.persist()` を要求
- オフライン: Service Worker。法令データは法令ごとに遅延読み込みし、選択した科目の分だけ端末に保存
- 検索: 条番号は正規化＋直接引き。見出し・本文のキーワード検索のみ軽量検索ライブラリを使う
- 公開: GitHub（公開リポジトリ）＋ GitHub Pages
- データ変換: Python スクリプト（開発 PC で実行し、生成 JSON をリポジトリに入れる）

### 4.2 リポジトリの置き場所
- `C:\Users\client02\ropo-marker\`（**amemiya リポジトリとは別**）
- 理由: 公開リポジトリにする必要があり、amemiya には案件の個人情報があるため混ぜない
- マーカーのデータは端末内にだけあり、リポジトリには入らない

### 4.3 条文データ構造
- 法令は **法令ID**（例: `129AC0000000089` = 民法）で識別し、法令名・略称は別の索引で持つ
- 条・項・号の入れ子を保持する:

```json
{
  "lawId": "129AC0000000089",
  "title": "民法",
  "abbr": ["民"],
  "fetchedAt": "2026-09-24",
  "toc": [ { "type": "編", "title": "第一編 総則", "children": [ ... ] } ],
  "articles": [
    { "key": "94", "label": "第九十四条", "caption": "（虚偽表示）",
      "paragraphs": [
        { "num": 1, "text": "..." },
        { "num": 2, "text": "...", "items": [ { "num": "1", "text": "..." } ] }
      ] }
  ],
  "suppl": [ { "id": "...", "label": "附則（平成二九年六月二日法律第四四号）", "articles": [ ... ] } ]
}
```

- 条の key: 枝番は `_` 区切り（第三条の二 → `3_2`）。附則は本則と別の配列に置き、衝突させない
- 削除条（「第○条 削除」）・条の範囲削除（「第○条から第○条まで 削除」）も表示できる形で残す

### 4.4 マーカーデータ構造（文字列アンカー方式）

```json
{ "id": "uuid", "lawId": "...", "loc": "94/p2/i1",
  "start": 12, "end": 30,
  "quote": { "exact": "善意の第三者", "prefix": "前項の規定による意思表示の無効は、", "suffix": "に対抗することができない" },
  "color": "yellow", "createdAt": "..." }
```

- `loc` は項・号単位の位置（条/項/号）。項をまたぐ選択は項ごとに分割して複数件で保存する
- 改正後は `quote` で探し直して付け直す。見つからないものだけ「要確認」の一覧に出す

### 4.5 参照リンク（段階的に実装）
1. 「第○条」「第○条第○項（第○号）」「第○条の○」（同一法令内）
2. 「前条」「次条」「前項」「次項」「前各項」
3. 「民法第○条」「借地借家法第○条」等の他法令参照（搭載法令名の辞書で照合）
4. 「同条」「同項」「同法」（直前の文脈を追う。精度を見て採否を判断）

- 参照検出は変換スクリプト側で行い、JSON に埋め込む（アプリ実行時には検出しない）
- 附則内の参照は改正法を指すことが多いので、当面リンク化しない

## 5. 改正対応フロー

1. 改正の検知: 定期的に（目安: 月1回）全法令を再取得して差分を取る。e-Gov の更新日を見て変わった法令だけ処理する
2. 変換スクリプトを再実行し、新旧 JSON を比較して変更条文の一覧を出す
3. 新しい JSON を公開する（GitHub に上げれば GitHub Pages に反映）
4. アプリは起動時に更新を検知し、マーカーを `quote` で付け直す。付け直せなかったものを「要確認」に出す
5. 変更履歴（日付・法令・条）をリポジトリの `data/changelog.json` に記録し、アプリでも見られるようにする

## 6. マーカー操作（段階3で試作して決定）

- 案①: 長押しで範囲を選択 → 画面下の3色ボタンで色を付ける
- 案②: 「マーカーモード」に切り替えて、指でなぞった範囲に色を付ける
- 両方を実機で試作し、使いやすい方を採用する

## 8. 今後の検討事項
- 条約・告示の取り込み要否（e-Gov に無いので、取り込むなら別の入手元と手入力が必要）
- 「同条」「同項」への対応可否（段階4の結果次第）
- 別表（`AppdxTable` 等）・表（`TableStruct`）の表示方法（段階1の3法令には無し。段階5で出てきたら対応）

## 9. 段階1の実装メモ（2026-09-24）
- 取得: `scripts/fetch_laws.py`（`data/laws.json` の法令名を完全一致で法令IDに変換 → `data/raw/` に XML 保存。`data/raw/` は git 管理外）
- 変換: `scripts/convert_laws.py`（→ `public/laws/{法令ID}.json` と `index.json`）
- 検証: `py -m unittest scripts/test_convert.py -v`（本文の欠落なし・条見出しと条番号の一致・最終条・既知の条文・附則の分離・未対応要素なし）
- API の応答は XML が Base64（文字列化の方式）で埋め込まれているので復号して保存する
- ルビは読みを捨てて本文だけ残す。号の段組み（Column）は全角空白で連結。本文とただし書は1つの文字列に連結
- 条の key は XML の Num 属性そのまま（枝番 `3_2`・範囲削除 `38:84`）

## 10. 段階2の実装メモ（2026-09-24）
- 画面: `src/`（React）。画面の切り替えは URL の `#/law/{法令ID}/{条key}/{項}`（GitHub Pages で再読み込みしても壊れないため）
- 検索: `src/search.js`（テスト `src/search.test.js`）。法令名・略称の最長一致（「民訴」を「民」より優先）→ 条・項・号を読む。範囲削除の条に含まれる番号はその範囲の条を開く
- 表示: 法令ごとに全条を1ページに並べる。画面外の条は `content-visibility: auto` で描画を省略し、移動後に位置が落ち着くまでスクロールをやり直す
- オフライン: vite-plugin-pwa（Workbox）で全ファイルを端末に保存。サーバー停止状態で民法709条が開けることを確認
- 公開: `.github/workflows/deploy.yml`（main への push でテスト → ビルド → GitHub Pages）
